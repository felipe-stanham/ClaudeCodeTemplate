The template in one picture

What it installs in a project: CLAUDE.md with the rules, 9 skills, 5 agents, hooks for 4 Claude Code events, a git hook, and 9 starter files in docs/templates/. At startup the session reads CLAUDE.md, MEMORY.md, docs/SYSTEM.md and the glossary, and confirms the template version. From then on it plans and orchestrates; the agents write the code.

From idea to code

Work matures in three steps: a Pitch (a half-formed idea), a Task (one bounded change, one branch) and a Project (several scopes, with a spec package). All of that is planning: it is written and pushed on dev, in the primary checkout. Code is always written in a worktree per branch, inside .claude/worktrees/.

Definition of Ready: what a task or scope needs before the implementer

  • Goal
  • Touches
  • Tasks
  • Acceptance Criteria
  • OUT of scope / No-gos
  • no Open Questions

The Execution Loop

How every task or scope is built, from its worktree. The main session writes no code: it invokes the agents in order and commits once at the end, with the code, the cached tests and the docs together.

testeropus · high4 · Test, and regression before dev → tstRead, Glob, Grep, Bash, Write, EditGenerates and caches scripts in tests/cache/ from the declarative criteria, and runs them.

Hooks: the hard gates

Hooks are scripts Claude Code runs by itself. settings.json points each event at a dispatcher.sh that is a fixed stub; all the logic lives in lib/dispatch.sh, so even an old template-sync can update it without breaking anything. Gates catch mechanical mistakes (wrong branch, secrets, missing docs); design judgment is left to the code-reviewer.

HookWhenEffect
pre-tool/01-check-docs-before-pushgit pushDeny when the unpushed commits change source but not the hand-written docs in docs/System/ (the generated map does not count), unless they carry Docs-Checked: no-changes — ….
pre-tool/02-protected-branchcommit, merge, cherry-pick or revert on main / master / tst, or a push to oneAsk: your approval is the promotion or hotfix authorization.
pre-tool/03-no-secretsgit add, git commitDeny when .env, .deploy-secrets or docs/local/ are not ignored, are tracked or staged; also when .claude/worktrees/ exists and is not ignored.
pre-tool/04-task-before-codeEdit / Write on codeDeny outside a task-T-* / scope-P-* branch whose task or project file exists. It does not see files written through Bash.
pre-tool/05-arch-check-before-pushgit pushDeny when .claude/arch-check.sh exists and fails or is not executable.
session-start/01-template-update-checka new session, or /clearTells Claude the version in use and, when a newer one is out, its CHANGELOG notes. Never changes anything.

Branches and worktrees

  • mainProduction. Only receives merges from tst (with your approval) and hotfixes.
  • tstStaging. Receives dev when the project is complete, the regression tests pass and docs-audit reports no differences.
  • devIntegration and planning. The primary checkout lives here. Never code directly.
  • task-T-xxxx-<desc>One per task, from dev (from main/tst for a hotfix).
  • scope-P-xxxx-N-<desc>One per project scope, from dev.
  • .claude/worktrees/<branch>One worktree per code branch, gitignored. Removed after the merge.

Template updates

Each project keeps its template version on line 1 of CLAUDE.md. When a session starts, the hook compares it with the CHANGELOG on main and, if the project is behind, shows you the release notes. Only when you say yes does template-sync run; it also repairs projects half-upgraded by older versions.

How this map stays current

Generated by map/build.py, with the engine of the system-map skill: never edit map/README.md, map/index.html or map/svg/ by hand. facts.py reads the version, skills, agents (model, effort and tools from their frontmatter), hooks and Execution Loop steps from Template/. python3 map/build.py --check fails when the committed map is stale, when the template has something the figures do not draw, or when a hook stops doing what the map says; the message names the file to edit.
